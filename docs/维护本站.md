# 内容维护与发布说明

本站地址：[高性价比人生指南](https://zhangjh024.github.io/HowToLiveBetter/)。

## 发布方式

GitHub Pages 从本仓库的 `main` 分支、根目录 `/` 发布。每次提交到 `main` 后，GitHub 会自动更新网站，无需安装依赖或手动构建。

可以直接在 GitHub 打开文件，点击编辑按钮，修改后提交到 `main`。发布进度在仓库的 [Actions](https://github.com/zhangjh024/HowToLiveBetter/actions) 查看，配置在 [Settings → Pages](https://github.com/zhangjh024/HowToLiveBetter/settings/pages) 查看。

## 添加自己的条目

1. 在 [book/](../book/) 找到对应章节，按现有格式添加条目，章节内编号保持唯一。
2. 条目标题下保留成本标签注释，填写成本、说人话、收益、证据等级、来源和备注。标签取值和写作要求见 [项目规则](../CLAUDE.md)。
3. 自己的经验按 C 级标注，并写明是个人经验；引用研究或官方文件时保留可核查来源。
4. 提交到 `main`。检索页直接读取 Markdown，新增条目会进入搜索和筛选。

如果确实需要新增章节，创建 `book/` 下的新文件后，还要把它的相对链接加入 [README 目录](../README.md#目录)；网站通过 README 中的章节链接发现正文文件。文件标题层级和条目格式请沿用已有章节。

条目总数或证据等级数量变化时，按项目规则同步 README 的统计、`index.html` 的介绍与元数据、`CLAUDE.md` 的目录简介，以及 `tools/og.html` 和分享图片 `og.png`。页面的检索结果数量会实时计算，介绍文字和分享图片里的数字需要维护。

## 添加自己的长文

网站侧边栏已有「个人体会」栏目，文章可直接在站内阅读。第一篇为 [第一](https://zhangjh024.github.io/HowToLiveBetter/personal.html?article=first)。

添加下一篇个人体会：

1. 在 `docs/个人体会/` 新建 Markdown 文件。第一行用 `# 标题`，正文支持段落、`##` / `###` 小标题、`**加粗**`、链接、引用和简单列表。
2. 在 `assets/articles.json` 数组里添加一项，填写唯一的英文 `id`、`title`、侧栏摘要 `subtitle`、介绍 `description`、收录日期 `date`、正文路径 `file`。`source` 和 `note` 可填写来源署名及必要说明。
3. 首页与阅读页的侧栏会自动显示文章，独立链接为 `personal.html?article=你的id`。顺序与数组一致；正文二级标题会自动生成阅读目录。
4. 在 `sitemap.xml` 加入新文章链接，提交到 `main` 后自动发布。个人体会独立展示，不计入指南条目总数和证据等级统计。

修改现有文章只需编辑对应 Markdown；修改标题、来源或介绍时同步修改 `assets/articles.json`。这些文章的正文由浏览器加载；`personal.html` 中的默认分享信息对应第一篇。

### 原有专题长文

在 `docs/` 新建 Markdown 文件，并在 README 中加入链接。如果希望读者能从网站首页打开，再把链接加入 `index.html` 的 `doc-links` 区域，地址使用本仓库的 `https://github.com/zhangjh024/HowToLiveBetter/blob/main/docs/文件名.md`。

现有网站通过 GitHub 阅读长文。放入 `docs/` 的长文不会自动变成搜索卡片；希望参与搜索的内容，需要按条目格式写进 `book/`。

## 本地预览

在仓库根目录运行：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:8000/`。不要双击 `index.html` 打开，浏览器需要通过 HTTP 读取 Markdown 正文。

## 同步原项目

合并原项目更新前，先检查自己的内容改动。合并后保留本站的域名、仓库链接与个人内容，避免将入口改回原作者的网站。
